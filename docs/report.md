# Отчёт по практической работе УП.02

**Тема:** Разработка учебной операционной системы с расширенной иерархической файловой системой.  
**Выполнил:** Багдасарян Николай Мисакович, студент 3 курса специальности 09.02.07 «Информационные системы и программирование».

## 1. Цель работы

Разработать учебную программу, моделирующую основные задачи операционной системы: авторизацию пользователей, работу с файлами и каталогами, процессы, использование памяти и журнал системных вызовов. Особое внимание уделено иерархической файловой системе с поддержкой вложенных каталогов, абсолютных путей, копирования и перемещения.

## 2. Предметная область

Настоящая операционная система управляет ресурсами компьютера. В учебном проекте StudyOS эти функции **имитируются** средствами Python и SQLite. Это делает программу наглядной и позволяет проверить логику работы без создания низкоуровневого ядра.

В программе существуют две роли. Администратор `admin` может управлять файлами и процессами всех пользователей. Обычный `user` ограничен своей домашней папкой `/home/<login>` и собственными процессами. Файлы и процессы сохраняются в базе данных, а shell принимает команды пользователя и передаёт их соответствующим модулям.

## 3. Стек технологий

- Python 3.10+ — язык реализации;
- SQLite (`sqlite3`) — встроенная реляционная база данных;
- `hashlib` (SHA-256), `hmac` — хранение и проверка паролей;
- `shlex`, `posixpath`, `getpass` — ввод команд, обработка путей и паролей;
- `unittest` — модульные тесты;
- GitHub Actions — проверка тестов при отправке изменений.

Внешних зависимостей проект не требует.

## 4. Архитектура и взаимодействие модулей

Пользователь вводит команды в `shell.py`; модуль преобразует удобные относительные пути в полные. Затем `syscalls.py` передаёт команду подсистеме и **в любом случае** записывает результат вызова в журнал. Выполнение операций распределено между `auth.py`, `fs.py` (и вспомогательными файловыми модулями), `scheduler.py`, `reports.py`. `kernel.py` хранит текущую сессию, каталог, счётчик PID и память; `db.py` предоставляет всем остальным модулям единый API для SQLite.

```text
Пользователь
    |
    v
shell.py (команды и аргументы)
    |
    v
syscalls.py (вызов + аудит OK / ERROR / DENIED)
    |
    +-- auth.py             -> пользователи
    +-- fs.py               -> файлы и каталоги
    |    +-- fs_core.py
    |    +-- fs_ops.py
    |    +-- fs_navigation.py
    |    +-- fs_transfer.py
    +-- scheduler.py        -> процессы и память
    +-- reports.py          -> статистика и журнал
             |
         kernel.py (сессия и ресурсы)
             |
          db.py (SQLite)
```

Дополнительные файлы `errors.py` и `cli_format.py` содержат классы ошибок и форматирование ответа. Код разделён на небольшие модули (не более 250 строк на файл); функции снабжены docstring, имена оформлены в `snake_case`.

## 5. Схема базы данных

В SQLite реализованы пять таблиц, указанных в задании:

| Таблица | Основные поля | Назначение |
| --- | --- | --- |
| `users` | `id`, `login`, `password_hash`, `role`, `created_at` | Регистрация, роли и вход |
| `files` | `id`, `name`, `path`, `parent_id`, `kind`, `content`, `owner_id`, `created_at` | Дерево файлов и каталогов |
| `processes` | `pid`, `name`, `state`, `owner_id`, `memory_kb`, `created_at`, `terminated_at` | Учёт процессов и памяти |
| `syscalls_log` | `id`, `name`, `arguments`, `user_id`, `status`, `created_at` | Журнал системных вызовов |
| `memory_state` | `id`, `used_kb`, `limit_kb` | Общий лимит и занятая память |

Связи: `files.parent_id -> files.id`, `files.owner_id -> users.id`, `processes.owner_id -> users.id`, `syscalls_log.user_id -> users.id`. Ссылочная целостность поддерживается внешними ключами SQLite (`PRAGMA foreign_keys = ON`). `path` уникален, а индексы ускоряют поиск по родителю и владельцу.

В дереве `/` — корень с `parent_id = NULL`. Например:

```text
/
└── home/
    └── student/
        └── projects/
            └── notes.txt
```

У объекта `notes.txt` полный путь `/home/student/projects/notes.txt`, а `parent_id` указывает на запись каталога `projects`.

## 6. Реализация файловой системы

**Создание:** `mkdir` создаёт каталог при существующем родителе, `touch` — пустой файл. Повторное имя в этом каталоге и отсутствие родительской папки вызывают ошибку.

**Чтение и запись:** `write_file` сохраняет текст в поле `content`, `read_file` возвращает его. Согласно заданию, чтение отсутствующего файла возвращает пустую строку (при проверке прав на путь).

**Удаление:** `rm` удаляет файл, а `rmdir` удаляет каталог рекурсивно с содержимым за счёт связи `ON DELETE CASCADE`.

**Навигация:** `pwd` возвращает текущую папку; `cd` выполняет переход; `ls` показывает непосредственных потомков; `tree` строит дерево с отступами.

**Копирование:** `copy` создаёт новые записи для объекта и всех его потомков, устанавливая новые `id` и `parent_id`, сохраняя содержимое.

**Перемещение и переименование:** `move` переносит объект вместе с веткой, меняя `parent_id` корневой записи переносимой ветки и полные пути всех потомков. `rename` использует тот же механизм без смены родительского каталога.

Все операции учитывают владельца и роль. Копирование каталога внутрь самого себя и перемещение в собственный подкаталог запрещены. Для системных папок `/` и `/home` ограничены разрушительные операции, чтобы не нарушить структуру модели.

## 7. Пользователи, процессы и журналирование

При первом запуске создаётся аккаунт `admin`; пароли хранятся в формате хэша SHA-256 (как предписано ТЗ), ввод через `getpass`. После регистрации создаётся личная директория. При отказе в доступе оболочка отображает понятную ошибку, а системный вызов записывается со статусом `DENIED`.

Команда `run` добавляет имитируемый процесс со своим PID, владельцем и объёмом требуемой памяти. Когда памяти недостаточно, процесс не создаётся. `ps` показывает список, `kill` завершает процесс и освобождает выделенную память, `mem` отображает свободную и занятую память. Состояние сохраняется в SQLite между запусками.

Журнал `syscalls_log` содержит имя операции, аргументы, пользователя, статус (`OK`, `ERROR` или `DENIED`) и время. Пароли при `login`/`register` заменяются на `[REDACTED]`. Команды `logs` и `report` показывают журнал и сводку по файлам, каталогам, объёму данных и недавним действиям.

## 8. Тестирование

Использован модуль `unittest`. Для каждого теста создаётся отдельная временная база SQLite. Обязательная команда из ТЗ:

```bash
python -m tests.test_fs
```

Дополнительно проверяются пользователи, память, процессы, журнал и отчёты:

```bash
python -m unittest discover -s tests -v
```
