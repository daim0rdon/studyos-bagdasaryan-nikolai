## О проекте

StudyOS — консольное приложение на Python, которое **имитирует** работу операционной системы. Это не полноценная загружаемая ОС: процессы и оперативная память моделируются программно, а файлы и каталоги существуют внутри базы данных SQLite, не затрагивая реальные пользовательские папки компьютера.

Главная часть проекта — **расширенная иерархическая файловая система**. Все объекты образуют дерево от корневого каталога `/`. У каждого объекта сохраняются `parent_id` и полный путь, поэтому доступны вложенные папки, рекурсивное удаление, копирование и перемещение целых веток.

Реализованы также регистрация и авторизация, роли `admin` / `user`, SHA-256 для хранения паролей (по условию учебного ТЗ), процессы и распределение памяти, аудит системных вызовов и отчёты.

## Как запустить

**Требуется:** Python **3.10 или новее**. Сторонние библиотеки не нужны. Работает на Windows, macOS и Linux.

1. Скачайте исходники (`Code` → `Download ZIP`) и распакуйте архив. Или клонируйте Git-репозиторий.
2. Откройте терминал в папке с файлом `main.py`.
3. Запустите:

```bash
python main.py
```

В некоторых системах вместо `python` нужна команда `python3`.

При **первом запуске** программа предложит придумать и повторить пароль администратора `admin` (минимум 6 символов), после чего войдёт в его профиль. Создаётся база `studyos.db`; при последующих запусках она сохраняет пользователей, файлы, процессы и журнал. Пароль не отображается при вводе.

Чтобы начать с пустой системой, можно удалить локальный файл `studyos.db` при **закрытом** приложении. Этот файл не включён в Git.

### Пример работы

Выполните после первого запуска, войдя как `admin`:

```text
whoami
mkdir /home/admin/projects
mkdir /home/admin/projects/notes
touch /home/admin/projects/notes/lesson.txt
write /home/admin/projects/notes/lesson.txt "Учебная операционная система"
cat /home/admin/projects/notes/lesson.txt
tree /home/admin
copy /home/admin/projects/notes /home/admin/notes-copy
move /home/admin/notes-copy /home/admin/notes-backup
rename /home/admin/notes-backup archive
run editor 128
ps
mem
kill 1
logs
report
```

**Важно:** в команде `kill 1` число `1` — пример PID для новой базы. В действующей базе узнайте правильный PID через `ps`.

Чтобы показать права доступа, выполните `register student` (задайте пароль), затем `logout`, `login student` и `touch /home/admin/secret.txt`. Приложение откажет обычному пользователю в создании файла вне его домашнего каталога и зарегистрирует `DENIED` в журнале.

Приглашение консоли выглядит так:

```text
admin@studyos:/home/admin$
```

## Права доступа

- `admin`: работает с пользовательскими объектами и процессами других владельцев; системные каталоги `/` и `/home` защищены от удаления для сохранения целостности дерева.
- `user`: работает с собственными объектами внутри `/home/<login>`, запускает и завершает только свои процессы.
- При запрещённом системном вызове отображается ошибка, а в `syscalls_log` сохраняется запись со статусом `DENIED`.

`/` и `/home` доступны для навигации, но чужие каталоги в списках обычного пользователя скрываются. Пароли хранятся в виде SHA-256 **строго по требованию учебного задания**; для реальных продуктов рекомендуется более стойкая схема хеширования паролей.

## Используемые технологии

- **Python 3.10+**, только стандартная библиотека;
- **SQLite 3** (`sqlite3`) — хранение объектов, пользователей, процессов, памяти, журнала;
- **unittest** — автоматизированное тестирование;
- **Git / GitHub Actions** — контроль версий и автоматические проверки.

## Структура проекта

```text
studyos/
├── main.py                     запуск одной командой
├── db.py                       база данных, таблицы и SQL API
├── kernel.py                   состояние ядра, пользователь, PID и память
├── auth.py                     учётные записи и роли
├── fs.py                       открытый интерфейс файловой системы
├── fs_core.py                  пути и проверка прав
├── fs_ops.py                   создание, чтение, запись, удаление
├── fs_navigation.py            pwd, cd, ls, tree
├── fs_transfer.py              copy, move, rename
├── scheduler.py                управление процессами и памятью
├── syscalls.py                 маршрутизация и журналирование
├── shell.py                    командная оболочка
├── cli_format.py               справка и вывод результатов
├── reports.py                  логи и статистика
├── errors.py                   исключения
├── tests/
│   ├── __init__.py
│   ├── test_fs.py              тесты файловой системы
│   └── test_system.py          тесты пользователей и процессов
├── docs/
│   ├── report.md               отчёт по работе
│   └── defense.md              сценарий демонстрации для защиты
├── .github/workflows/tests.yml
└── README.md
```

В базе создаются **5 таблиц**: `users`, `files`, `processes`, `syscalls_log`, `memory_state`. У корня `/` значение `parent_id` равно `NULL`; у остальных объектов `parent_id` ссылается на родительский каталог.

## Как запустить тесты

Требуемая в ТЗ команда:

```bash
python -m tests.test_fs
```

Все тесты, включая пользователей, процессы, память, журнал:

```bash
python -m unittest discover -s tests -v
```

**Итог локальной проверки:** 20 тестов файловой системы, 13 дополнительных системных тестов; всего **33 теста, все проходят**. Каждый тест работает с временной базой, поэтому данные пользователя не затрагиваются. GitHub Actions запускает проверки автоматически для Python 3.10, 3.12 и 3.13.
